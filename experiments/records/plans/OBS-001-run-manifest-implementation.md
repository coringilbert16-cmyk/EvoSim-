# OBS-001 run manifest — implementation slice

**Status:** Implemented on `fix/obs-001-run-manifest`; pending CI and review.  
**Depends on:** PR #400 (opportunity coverage).  
**Scope:** Provenance sidecar for environmental chemistry diagnostics. No chemistry or simulation behavior changes.

## Contract

Each environmental chemistry diagnostics run writes a sidecar named
`<diagnostics-path>.manifest.json`. The existing JSONL remains unchanged and
is the raw observation record.

The sidecar uses:

- `schema: evosim.experiment_manifest`
- `schema_version: 1`
- UTC-independent Unix epoch millisecond timestamps (`started_at_unix_ms`,
  `completed_at_unix_ms`) to avoid adding a date/time dependency
- measured wall-clock elapsed seconds from the observation loop's monotonic
  clock, not requested duration or planned ticks
- actual start/end ticks
- repository, commit, workflow, run ID, attempt, and run URL when supplied by
  GitHub Actions environment variables
- experiment, research-plan, and condition identifiers when supplied through
  `EVOSIM_EXPERIMENT_ID`, `EVOSIM_RESEARCH_PLAN`, and
  `EVOSIM_CONDITION_ID`
- captured initial conditions and a SHA-256 hash of the canonical serialized
  captured-configuration object
- raw JSONL artifact path, byte size, and SHA-256 checksum after successful
  completion
- warnings and explicit captured-configuration scope

The configuration hash is intentionally labeled
`configuration_completeness: captured_fields_only`. The first slice hashes
the run conditions already available to the recorder (seed, requested duration,
planned ticks, diagnostic interval, starting inventory/counts, pile sizes, and
hotspot). It does not claim to fingerprint every hidden/default simulation
parameter. Expanding this to a complete configuration contract requires a
separate inventory of all relevant environment and physics settings.

## Interrupted runs

The recorder writes a `running` manifest after the initial JSONL header and
snapshot have been flushed. If the process exits before `finish`, the sidecar
remains `running`, with no final elapsed duration or checksum. A successful
`finish` replaces it with `completed` and records final ticks, elapsed time,
artifact size, and checksum.

A forcibly terminated process may not flush its final JSONL buffer; the
manifest therefore does not claim the partial artifact is complete or
checksummed. It preserves run identity and the fact that completion was not
observed.

## Validation

`tools/experiment_manifest.py` validates schema/version, time and tick
ranges, required configuration shape, SHA-256 formatting, and (for completed
runs) raw artifact existence, size, and checksum. Running manifests are checked
for structure and artifact presence without requiring a final checksum.

The standard Rust CI smoke workflow now runs this validator, tests it with
offline unit tests, and uploads the sidecar alongside the raw JSONL.

## Limitations and follow-up

- Research workflows must set the three `EVOSIM_*` experiment metadata
  variables. Missing values remain null and generate warnings.
- Local runs without GitHub Actions metadata retain null workflow/build fields
  and generate warnings; no commit or run identity is guessed.
- Analyzer version is tied to the repository commit SHA. Individual analyzer
  file hashes and output schema versions are not yet recorded.
- The first slice fingerprints only captured configuration fields, not every
  simulation setting.
- Artifact upload IDs/URLs are created after the simulation process exits and
  are therefore not included in this sidecar yet. The future analysis index
  should bind uploaded artifact references without mutating the immutable
  original manifest.
- A failed process is represented as `running` unless an external workflow
  finalizer can reliably classify its exit. The sidecar never claims a failed
  run completed.
